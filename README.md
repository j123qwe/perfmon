# perfmon

Backhaul link monitoring for SD-WAN remote routers, packaged with Kustomize.

```
targets.yaml ──> vmagent ──scrape──> blackbox_exporter ──ICMP/HTTP/DNS──> targets
                    │        (same pod, host network)
                    └─remote write─> VictoriaMetrics (PVC) <── Grafana <── Ingress (TLS)
```

| Component | Kind | Notes |
|---|---|---|
| `prober` | DaemonSet | blackbox_exporter + ISP exporter + vmagent, `hostNetwork`, loopback listeners only. One vantage point per node; samples are labelled `probe_node`. |
| `victoriametrics` | StatefulSet | Single node, 10Gi PVC, 30 day retention. |
| `grafana` | Deployment | Stateless; datasource and dashboards provisioned from ConfigMaps. Anonymous users are Viewers. |

## Layout

```
base/                        portable, site-independent
  targets.yaml               default targets (ping 1.1.1.1 every 30s)
  prober/blackbox.yml        probe modules: icmp, http_2xx, dns_udp
  prober/scrape.yml          vmagent config (rarely edited)
  prober/isp-exporter.py     public egress IP and ISP lookup (configurable refresh)
  grafana/dashboards/*.json  generated by hack/gen-dashboards.py
overlays/example/            template overlay (the only one tracked in git)
overlays/<site>/             one directory per router/cluster (gitignored)
  targets.yaml               this site's targets
  kustomization.yaml         ingress host, issuer, retention
  grafana-admin.env          admin login
```

## Deploy

```bash
export KUBECONFIG=~/.kube/config
kubectl apply -k overlays/<site>
```

Grafana is served at the overlay's ingress host (no login needed to view). The
admin login for editing is in `overlays/<site>/grafana-admin.env`.

### Default HTTPS application

For Traefik, uncomment `grafana-default-ingress.yaml` under `resources` in the
site's `kustomization.yaml` and re-apply. Set its `ingressClassName` to the
same Traefik class as the named Grafana ingress. The separate, low-priority
HTTPS catch-all sends otherwise unmatched hosts and paths to Grafana, including
requests such as `https://192.168.77.66/`. Other matching Traefik routes
normally take precedence; another catch-all or explicit priorities can cause
conflicts. This applies to traffic reaching Traefik, not necessarily every
worker-node IP: ensure the load balancer or node exposes Traefik on port 443.
HTTP routing and HTTP-to-HTTPS redirects are not configured by this option.

The existing hostname and its cert-manager certificate remain unchanged. An IP
address does not match that hostname certificate, so Traefik normally presents
its default certificate for IP access. Browsers will warn unless Traefik's
default TLS certificate has the IP address as an IP subject alternative name
and is trusted by the client. A private IP needs a suitable private CA or
self-signed certificate trusted by clients; configure it in Traefik's default
TLS store. Strict SNI checking must not reject clients without SNI. Enabling
this option exposes anonymous Grafana viewing on unmatched hosts as well.

To disable it, remove the resource and delete the previously applied ingress
(`kubectl -n perfmon delete ingress grafana-default`); `kubectl apply -k` does
not remove resources omitted from the overlay.

## Add, remove or change targets

Edit `overlays/<site>/targets.yaml` and re-apply. The prober restarts with the
new list in a few seconds.

```yaml
- targets: ["1.1.1.1"]
  labels:
    module: icmp        # icmp | http_2xx | dns_udp | your own module
    name: cloudflare    # label shown in Grafana
    interval: 1s        # default 30s
```

- `timeout` defaults to the interval, capped at 5s. A probe that has not
  answered by then counts as lost, so at `interval: 1s` any reply slower than
  0.9s is loss.
- HTTP and DNS placeholders are in the file, commented out. Uncomment them and
  the "HTTP / DNS" tab fills in.
- Removing a target stops new samples; its history stays until retention expires.

### Pin a probe to a specific uplink or tunnel

Probes run in the router's network namespace and follow its routing table. To
force a source address, add a module with `source_ip_address` (example in
`base/prober/blackbox.yml`), enable the `perfmon-blackbox` override in the
overlay, and set `module: <that name>` on the target.

## New site

```bash
cp -r overlays/example overlays/<site>
cp overlays/<site>/grafana-admin.env.example overlays/<site>/grafana-admin.env
```

Then set the ingress host, ingress class and ClusterIssuer in
`kustomization.yaml`, edit `targets.yaml`, and set a real password in
`grafana-admin.env`. Site overlays are gitignored; only `overlays/example` is
tracked.

## Dashboard

Grafana 13.2.6 displays one **Network performance** dashboard with native
**Backhaul**, **HTTP / DNS**, and **ISP** tabs, using the v2 dashboard schema.
Probe node and time range selections are shared; the ICMP target filter applies
only to Backhaul. The existing backhaul URL remains valid; the separate
HTTP/DNS dashboard is replaced by its tab.

`python3 hack/gen-dashboards.py` regenerates the JSON; edit the script, not the
JSON. The dashboard is read-only in the UI because Grafana has no persistent
storage here. Focused checks: `python3 -B hack/test-perfmon.py`.

### ISP information

Backhaul includes an **ISP over time** timeline aligned with the performance
graphs and their shared crosshair. Each node/ISP pair has its own labeled lane,
so switches (including a return to a previous ISP) can be compared with latency
and loss. Maximum RTT, packet loss and Reachability sit above the full-width
average RTT graph.
The ISP tab continues to show current connection details.

The ISP tab shows each probe node's public IP, IP version, ASN, ISP,
organization, approximate country/region/city, postal code, coordinates and
timezone, using ip0.me's client information. It describes the
**node's internet exit**, not the viewer's browser. Browser-specific HTTP/TLS
details and Cloudflare datacenter/RTT fields are not collected.

A small, standard-library Python sidecar makes an HTTPS lookup to
[ip0.me/json](https://ip0.me/json) at startup, then waits five minutes
between lookups by default.
The provider sees the node's public IP, but receives no credentials, probe
targets or application data. Nodes need outbound HTTPS access to this service.
The endpoint's `as_organization` supplies both ISP and Organization; it does
not provide a separate consumer ISP name. Each node makes about 288 lookups/day
with the default interval. Check provider terms and limits before large
deployments; do not assume the endpoint is unlimited.

To check every minute, add this entry under `patches` in your site's
`kustomization.yaml` (also provided as a commented example in
`overlays/example/kustomization.yaml`), then re-apply the overlay:

```yaml
- target: {kind: DaemonSet, name: prober}
  patch: |-
    apiVersion: apps/v1
    kind: DaemonSet
    metadata:
      name: prober
    spec:
      template:
        spec:
          containers:
            - name: isp-exporter
              args: ["--interval-seconds", "60"]
```

The value must be a positive integer in seconds; invalid values fail startup.
This setting applies to each node's ISP exporter, not individual entries in
`targets.yaml`; probe frequency and the ISP metric's 30-second scrape interval
are unchanged. Changing the pod arguments triggers a rollout.
**One-minute lookups make about 1,440 requests/day per node**. Ensure the
provider permits this frequency, including combined traffic from nodes sharing
a public IP.

The sidecar follows the node's default routing and address-family selection.
It does not discover all uplinks or inherit blackbox `source_ip_address`
settings. NAT, VPNs and proxies can make the reported ISP/location describe an
exit gateway; geolocation is approximate.

The tab includes lookup status, exporter reachability, and age of the last
successful lookup. Failed lookups are logged and clear connection details
rather than presenting old information as current. A failed scrape shows the
exporter as down; consult freshness before trusting any remaining values.
Connection details are hidden when the lookup fails, the exporter is down, or
the last successful lookup is at least two configured lookup intervals plus
60 seconds old (eleven minutes by default; three minutes for one-minute
lookups). The age pane shows elapsed seconds without a fixed color threshold.
The exporter exposes `perfmon_isp_lookup_interval_seconds` so freshness checks
use each node's interval. Older history without that metric retains the
original five-minute default.
Metrics are stored in VictoriaMetrics under the configured retention policy.
The timeline queries those historical samples, not today's ISP applied to old
probes. Failed, unreachable or stale lookups leave gaps rather than joining
across unknown periods; retired ISP series are excluded after a switch.
ISP attribution is the last observed **default-egress** provider, not an exact
per-probe measurement: a switch can take one configured lookup interval plus
lookup time and the next 30-second scrape to appear. Brief switches between
lookups may be missed, and probes pinned to another uplink may use a different
ISP. The timeline itself needs no additional lookup requests or per-ISP labels
on probe metrics. History is available
where ISP samples were collected, up to the configured retention period.
Because anonymous viewers can see public IP and location details, restrict
ingress or disable anonymous access if that information should not be public.

## Retention and sizing

Retention is `-retentionPeriod` on the VictoriaMetrics StatefulSet (patched in
the overlay). Each ICMP target produces about 10 series. At a 1s interval that
is roughly 0.9M samples per target per day, around 1 MB/day on disk, so the
10Gi volume is ample for dozens of 1s targets at 30 days.
